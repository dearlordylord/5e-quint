# Battle Visualizer — Rendering Architecture

**Renderer:** SVG-in-React + Motion (framer-motion successor, `motion` npm package). Selected for maximum testability — SVG elements are DOM nodes, queryable by RTL, snapshot-testable in vitest without a browser. See `ENGINE_RESEARCH.md` for full comparison of 15+ engines.

## Prerequisites / What Already Exists

- **Battle machine** (`battle-machine.ts`) — XState state machine, MBT-validated against Quint spec. Handles attacks, spellcasting, reaction interrupts (counterspell chains up to 4 deep), AoE resolution, concentration, legendary actions, movement with opportunity attacks.
- **Flexible init** — `BATTLE_INIT` takes `InitCreatureConfig[]` (any number of creatures with configurable kind, slots, class levels, prepared spells).
- **Demo scenario** (`app/src/demo/fireball-selfishness.ts`) — 16-event `BattleEvent[]` sequence with passing test. 6 wizards (25 HP each, 3v3), Fireball + CS chain + AoE resolution. Test in `fireball-selfishness.test.ts` verifies B/C/D/E unconscious, F alive at 11 HP.
- **App structure** — Vite + React 19 + Tailwind v4. Pathname routing in `entry.tsx` (`/simulator`, `/machine-viz`, `/`). Battle viz = new route (e.g., `/battle`).
- **Motion NOT installed yet** — add `motion` to package.json.
- **Rendering is SVG only** — no canvas, no PixiJS, no WebGL. Pure `<svg>` elements + Motion for animation. If SVG hits a performance wall later, swap renderer; scene state layer stays.

## Demo: "Fireball Selfishness" — Visual Sequence

What a game engine/renderer should show, step by step:

1. **Grid field** with 6 wizard tokens (A,B,C left / blue, D,E,F right / red). Each has HP bar (full), slot pips, name label.
2. **A's turn starts.** A highlighted as active creature.
3. **A casts Fireball.** Cast bar fills above A's head (Ragnarok Online style — purely visual, ~500ms). AoE zone circle appears centered on target point (between the two teams). Spell name "Fireball" shown.
4. **Interrupt phase.** Field dims. "INTERRUPT" overlay. D's token highlights — D counterspells (cast bar, slot pip consumed). Then B counter-counterspells D. Then E counter-counterspells B. Then C counter-counterspells E. Each shows briefly with cast bar + slot pip consumed.
5. **Chain resolves.** Interrupt overlay fades. Fireball AoE zone pulses / fire effect.
6. **AoE resolves per target.** B,C,D,E each flash red, HP bar drops to 0, token greys out (Unconscious). F flashes but HP bar drops only to ~44% (14 damage on 25 HP). F stays colored.
7. **F's after-damage reaction.** Brief interrupt flare. F highlighted. "Absorb Elements" annotation (NOTE: Absorb Elements is not SRD — used here purely as a visual annotation for the demo, not a modeled mechanic. The battle machine treats this as BATTLE_AFTER_DAMAGE_PASS). F passes. Interrupt ends.
8. **Back to active turn.** 4 tokens grey/fallen, A and F standing. A's slot pip consumed from Fireball.

Creature tokens are **static circles** for now (styled by team color). Sprite images to be generated by AI models later — architecture should support swapping circle for `<image>` in CreatureToken component. Future: token size should scale with creature Size (Medium=1sq, Large=2x2, etc.).

## AoE Grid Math

- Grid square = 5 feet (SRD 5.2.1)
- Fireball = 20ft-radius sphere
- Grid discretization: "center of square within radius" (SRD doesn't specify — documented in ASSUMPTIONS.md)
- ~48 affected squares for a 20ft-radius sphere
- AoE targets a POINT on the grid, NOT creatures. Creatures in the zone are affected. Visually: show the circle zone, not targeting lines to creatures.
- Future: cover/obstruction affects AoE line-of-sight (SRD: "If all straight lines extending from the point of origin to a location are blocked, that location isn't included"). Not modeled now.

## Four Layers

```
BattleContext (XState snapshot)
    | deriveSnapshot(ctx, meta) — Layer A
    v
SceneSnapshot (deterministic, no time, no pixels)
    | diffSnapshots(prev, curr) — pure delta
    | Director.step(event, snapshot, delta, clock) — Layer B
    v
SceneSnapshot + VisualCueState
    | computeLayout(snapshot, cues, config) — Layer C
    v
LayoutState (pixels)
    | React props — Layer D
    v
<BattleField> SVG + Motion
```

### Layer A: Scene Snapshot (pure, deterministic)

`(BattleContext, ScenarioMeta) -> SceneSnapshot`

No coordinates, no time, no animation. Grid positions and game-unit measurements only. Creatures in initiative order (deterministic for tests). AoE radius in feet (converted to squares in Layer C).

**Presentation projections:** `CreatureSnapshot` contains derived fields (`hpRatio`, `totalSlotsRemaining`, etc.) computed once from `BattleCreatureState`. This is a deliberate presentation-layer projection at the API boundary — consumers never reach into `BattleCreatureState`. Both raw HP values (for labels) and ratios (for bar sizing) are needed.

```typescript
/** Scenario-provided data not in BattleContext (spatial, visual, identity).
 *  Keyed by stable eventId to survive scenario edits. */
interface ScenarioMeta {
  names: Record<string, string>                                    // creatureId -> display name
  teams: { blue: string[]; red: string[] }
  gridPositions: Record<string, { row: number; col: number }>      // creatureId -> grid pos
  aoeTargetPoints: Record<string, { row: number; col: number }>    // eventId -> grid point
  spellAnnotations: Record<string, string>                          // eventId -> spell name
}

/** Deterministic projection of BattleContext. No time, no animation. */
interface SceneSnapshot {
  creatures: ReadonlyArray<CreatureSnapshot>  // initiative order
  phase: PhaseSnapshot
  aoeZones: ReadonlyArray<AoEZoneSnapshot>
  round: number
  activeCreatureId: string | null  // null during init/edge transitions
}

interface CreatureSnapshot {
  id: string
  name: string
  team: "blue" | "red"
  gridPos: { row: number; col: number }
  // Presentation projections derived from BattleCreatureState — not canonical state.
  // Raw values for labels, ratios for bar sizing.
  hpRatio: number             // hp / maxHp
  currentHp: number
  maxHp: number
  tempHp: number              // visually distinct from HP per ubiquitous language
  unconscious: boolean        // hp === 0 && !dead (NOT the Unconscious condition alone)
  dead: boolean
  reactionAvailable: boolean
  concentrating: boolean      // concentrationSpellId !== ""
  exhaustion: number          // 0-6
  totalSlotsRemaining: number // sum of slotsCurrent (visual summary, not game-mechanical)
  totalSlotsMax: number       // sum of slotsMax
  isActive: boolean           // this creature's turn is current
  conditions: ReadonlyArray<Condition>  // typed, labels at render edge only
}
// Note: "alive" is not a field — derive !dead at render edge if needed.

// Derived from PendingInterrupt["tag"], not hand-written
type InterruptKind = PendingInterrupt["tag"]

type PhaseSnapshot =
  | { type: "activeTurn" }
  | { type: "interrupt"; interruptKind: InterruptKind; reactorId?: string }
  | { type: "aoeResolving"; spellName: string; remainingCount: number }
  | { type: "movement" }
  | { type: "legendaryAction" }

interface AoEZoneSnapshot {
  zoneId: string                              // stable identity for React keys
  centerGridPos: { row: number; col: number } // from scenario metadata
  radiusFeet: number                          // game units — converted to squares in Layer C
  damageType: DamageType                      // typed, for visual catalog color lookup
  spellName: string
}
```

**Ordering:** `creatures` array always in initiative order (deterministic, avoids test diffs from Map iteration).

**Testing:** Pure vitest. Assert creature HP ratios, phase types, AoE zone positions. No DOM, no time.

### Snapshot Delta (pure function)

`diffSnapshots(prev, curr) -> SnapshotDelta`

```typescript
interface SnapshotDelta {
  damageTaken: Record<string, number>        // id -> positive amount
  healingReceived: Record<string, number>    // id -> positive amount
  becameUnconscious: ReadonlyArray<string>   // ids that transitioned to unconscious
  conditionsGained: Record<string, ReadonlyArray<Condition>>  // id -> new conditions
  conditionsLost: Record<string, ReadonlyArray<Condition>>    // id -> removed conditions
  reactionsSpent: ReadonlyArray<string>
  slotsExpended: ReadonlyArray<string>
  phaseChanged: boolean
  newAoeZones: ReadonlyArray<AoEZoneSnapshot>
}
```

### Layer B: Director (owns time, injectable clock)

`Director.step(event, snapshot, delta, clock) -> VisualCueState`

Module with injectable clock, thin `useDirector` React hook wrapper. `step()` is called once per event — it returns a static `VisualCueState` snapshot. Temporal animations (cast bar fill 0->1 over 500ms) are handled by Motion's prop transitions in Layer D, not by repeated Director calls. The Director determines WHAT should animate (cast bar present, damage flash true), Motion determines HOW (duration, easing).

```typescript
interface VisualCueState {
  castBar: { casterId: string; spellName: string; progress: number } | null
  interruptOverlay: { opacity: number; label: string }
  creatureCues: Record<string, CreatureCue>
  autoAdvanceDelay: number  // ms until next auto-step (0 = manual mode)
}

interface CreatureCue {
  damageFlash: boolean
  justBecameUnconscious: boolean
  castingGlow: boolean
  reactionUsed: boolean       // briefly true after spending reaction
  conditionGained: boolean    // briefly true after gaining a condition
}

/** Per-event-type timing config. Uses BattleEvent["type"] union — can't drift. */
interface PlaybackTiming {
  defaultDelayMs: number
  overrides: Partial<Record<BattleEvent["type"], number>>
}
```

### Layer C: Layout (pure math)

`(SceneSnapshot, VisualCueState, LayoutConfig) -> LayoutState`

Converts grid positions to pixel coordinates, feet to squares to pixels, computes bar dimensions, AoE circle radii.

```typescript
interface LayoutConfig {
  cellSize: number        // px per grid square (e.g., 60)
  gridCols: number
  gridRows: number
  tokenRadius: number     // px (e.g., 22)
  barWidth: number        // px (HP bar, cast bar)
  barHeight: number       // px
}

interface LayoutState {
  viewBox: { width: number; height: number }
  gridLines: ReadonlyArray<{ x1: number; y1: number; x2: number; y2: number }>
  creatures: ReadonlyArray<CreatureLayout>
  aoeZones: ReadonlyArray<AoELayout>
  interruptOverlay: { opacity: number; label: string | null }
}

interface CreatureLayout {
  id: string
  cx: number; cy: number            // token center px
  tokenRadius: number
  teamColor: string                 // hex
  opacity: number                   // 1 normal, 0.3 unconscious, 0 dead
  label: string                     // display name
  hpBar: BarLayout
  tempHpBar: BarLayout | null       // visually distinct, only if tempHp > 0
  castBar: BarLayout | null         // null if not casting
  slotPips: { x: number; y: number; filled: number; total: number }
  damageFlash: boolean
  castingGlow: boolean
  justBecameUnconscious: boolean
}

interface BarLayout {
  x: number; y: number
  totalWidth: number; fillWidth: number; height: number
  color: string
}

interface AoELayout {
  zoneId: string
  cx: number; cy: number; r: number
  color: string; opacity: number
}
```

### Layer D: SVG + Motion (thin rendering)

Components: `BattleField`, `GridOverlay`, `CreatureToken`, `AoEZone`, `InterruptOverlay`, `BattleLog`.

```tsx
<svg viewBox={`0 0 ${layout.viewBox.width} ${layout.viewBox.height}`}>
  <GridOverlay lines={layout.gridLines} />
  {layout.aoeZones.map(z => <AoEZone key={z.zoneId} {...z} />)}
  {layout.creatures.map(c => <CreatureToken key={c.id} {...c} />)}
  {layout.interruptOverlay.opacity > 0 && <InterruptOverlay {...layout.interruptOverlay} />}
</svg>
```

**Scrubbing:** `BattleLog` supports click-to-jump (same pattern as existing `TransitionLog`). Jumping replays events from scratch through the battle actor, recomputes `deriveSnapshot()` at target step. Deterministic — same event sequence always produces same snapshot.

## Files

```
src/battle-scene/
  scene-snapshot.ts + test     # Layer A
  snapshot-diff.ts + test      # Delta
  director.ts + test           # Layer B (injectable clock)
  layout.ts + test             # Layer C
  visual-catalog.ts            # Spell/damage/condition visuals
  BattlePage.tsx               # Route entry
  BattleField.tsx              # <svg> root
  GridOverlay.tsx              # Grid lines
  CreatureToken.tsx            # Token + bars + slots
  AoEZone.tsx                  # Circle overlay
  InterruptOverlay.tsx         # Dimming + label
  BattleLog.tsx                # Event timeline (reuses TransitionLog jumpTo pattern)
```

Note: feature-folder pattern (`src/battle-scene/` contains both pure TS and React). Differs from existing split (`src/features/` pure, `src/components/` React) but keeps the rendering pipeline co-located. Acceptable per project philosophy ("no external consumers", "change any layer").

## Build Order (Task DAG)

```
T1 ──→ T2 ──→ T5 ──→ T6 ──→ T8
 │              ↑      ↑
 ├──→ T4 ──────┘──→ T7 ┘
 │
T3 ──→ T4
```

```
[T1] scene-snapshot.ts + test    deps: none         (Layer A — pure functions)
[T2] snapshot-diff.ts + test     deps: T1           (needs SceneSnapshot types)
[T3] visual-catalog.ts           deps: none         (pure data, no logic)
[T4] layout.ts + test            deps: T1, T3       (needs SceneSnapshot + visual catalog + LayoutState defined here)
[T5] director.ts + test          deps: T1, T2       (needs SceneSnapshot + SnapshotDelta)
[T6] BattlePage.tsx              deps: T1, T4, T5   (route entry, wires actor + director + layout)
[T7] SVG components              deps: T4, T6       (BattleField, CreatureToken, AoEZone, etc.)
[T8] wire /battle route          deps: T6, T7       (add to entry.tsx)
```

**Parallelism:** T1 and T3 can run concurrently. T2 and T4 can run concurrently once T1 is done. T5 needs T1+T2. Tasks T1-T5 are pure TS with vitest (no React, no DOM, no animation library). Tasks T6-T8 are React/SVG and require `motion` installed.

**Each task is atomic:** produces files, has tests (where applicable), can be verified independently with `npx vitest run`.

**Pre-task: update demo metadata.** `FIREBALL_SELFISHNESS_META` needs `gridPositions` and `aoeTargetPoints` added, and keys changed from numeric indices to stable event IDs. Do this before T1 so tests can use the real demo data.

## Resolved Design Decisions (25)

| # | Decision |
|---|----------|
| 1 | 4 layers: projection / director / geometry / SVG |
| 2 | Director owns all temporal state (cast bars, flashes, delays) |
| 3 | Manual + auto-play stepping. Timing typed as `Partial<Record<BattleEvent["type"], number>>` |
| 4 | AoE target point in scenario metadata, keyed by stable eventId |
| 5 | Spell visual catalog separate from mechanical catalog, 3 sub-catalogs with defined shapes |
| 6 | Grid positions in scenario metadata |
| 7 | Cast bar progress owned by Director, not scene snapshot |
| 8 | Director = module + thin useDirector hook wrapper. step() called once per event. |
| 9 | CreatureSnapshot = presentation projection at API boundary. Justified: both raw HP and ratio needed. |
| 10 | `aoeZones` as array (supports overlapping effects) |
| 11 | `diffSnapshots()` separate pure function, Director receives delta |
| 12 | Interrupt kind derived as `PendingInterrupt["tag"]`, no hand-written union |
| 13 | `activeCreatureId: string \| null` |
| 14 | Metadata keyed by stable eventId, not array index |
| 15 | Damage/healing split (positive amounts, no sign confusion) |
| 16 | Creatures in initiative order (deterministic for tests) |
| 17 | Conditions typed as `Condition`, labels at render edge only |
| 18 | AoE zones have `zoneId` for React keys |
| 19 | HP and temp HP visually distinct (separate bars) |
| 20 | No `alive` field — derive `!dead` at render edge |
| 21 | AoE radius in feet in Layer A, converted to squares/pixels in Layer C |
| 22 | SnapshotDelta tracks condition changes (gained/lost) |
| 23 | `becameUnconscious` / `justBecameUnconscious` terminology (not "knocked out") |
| 24 | Scrubbing via jumpTo: replay events from scratch, recompute snapshot |
| 25 | Feature-folder pattern for battle-scene (co-located pure TS + React) |
