## Scope

In scope:

- SRD 5.2.1 level-2 class-feature pressure.
- SRD cantrip, level-1 spell, and level-2 spell pressure as reported by the
  generated metric.
- `@dnd/battle-runtime`, `@dnd/character-creation-runtime`,
  `@dnd/character-sheet-runtime`, Surface content, and coverage evidence when
  they are the correct owner.
- Runtime-detached table adjudication closures when the application should not
  model the rule result.
- Table-supplied runtime witnesses when the runtime owns the consequence but
  the table owns geometry, visibility, object state, or scene facts.

Out of scope:

- `plans/ACTIVE_PLAN.md`.
- Companion/familiar implementation. `find_familiar` remains excluded by the
  companion worktree. `find_steed` and `druid_wild_companion` are boundary
  tasks: either route them to the companion owner or add metric-visible
  exclusion/closure, but do not implement companion AI here.
- Loop L language access work for `druid_druidic` and `rogue_thieves_cant`.
- Broad map/pathfinding/rendering/detection engines. Use table-supplied
  witnesses or runtime-detached closures where that is the product boundary.

## Review Loop

Use implementer, reviewer, handback until `accept`, then decider. The reviewer
loop must include RAW traceability, ubiquitous-language/domain-language,
architecture/connascence, and code-review passes. Fix every reasonable finding,
explicitly reject only findings with a concrete reason, and repeat until no
reasonable findings remain.

Reviewers should reject:

- support claims without executable owner evidence;
- catalog admission treated as runtime support;
- adding table-detached detection/social/exploration facts as runtime state;
- object/geometry/light/pathfinding derivation hidden inside spell support;
- duplicate Spell Definition, Spell Access, Spell Invocation, or Spell Effect
  state;
- companion behavior in this plan without an explicit owner handoff.

## Common Task Contract

Every task starts by reading:

- the matching row in `plans/unit-profile-coverage/LEVEL1_2_FULL_SUPPORT.md`
  or `plans/unit-profile-coverage/SRD_UNIT_INVENTORY.md`;
- the local RAW source under `.references/srd-5.2.1/`;
- `UBIQUITOUS_LANGUAGE.md`, especially Spell Definition, Spell Access, Spell
  Invocation, Spell Effect, Character Sheet, Ability Check, Saving Throw,
  Attack Roll, Speed, Movement, and Condition terms as relevant;
- existing Surface content, Unit claims, Unit profiles, and owner-evidence
  manifests for the Unit id.

Every task outputs one of these concrete end states:

- `supported-profile` plus deterministic admission/projection evidence and
  focused runtime or character-owner tests;
- `profile-subset-supported` only when the supported subset is executable and
  every residual has a precise accepted closure kind;
- `unsupported-profile` with an accepted runtime-detached closure when the rule
  is outside product runtime;
- a companion-owner exclusion or handoff when the task is a companion boundary;
- a smaller follow-up split only if RAW proves the listed task cannot fit in one
  coding session, with the original metric row still left in a precise blocked
  state rather than generic "todo" wording.

Every implementation task runs:

- relevant focused package tests;
- package typecheck for touched packages when dependencies are available;
- `pnpm unit-profile-coverage:check --write`;
- `pnpm unit-profile-coverage:check`;
- `git diff --check`;
- reviewer-loop convergence.

Do not run battle-runtime MBT unless the task changes promoted battle-runtime
behavior and focused tests cannot cover the changed boundary. If MBT is needed,
use the repository MBT scarcity protocol.
