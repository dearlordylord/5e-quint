## Purpose

This Ralph plan is the seed plan for converging the dirty Rust cleanroom target
toward the source-owned battle reducer architecture. It is intentionally not a
75-95 task implementation list. Its job is to produce the machine-readable
backlog and hardened evidence rules that make that larger list real instead of
speculative.

Global goal:

> All battle behavior that needs battle-level orchestration is routed through
> `BattleState -> discover_battle_acts -> resolve_battle_subject`, with source
> QNT route authority and target evidence from actual Rust reducer execution.

The plan is successful only when the generated backlog lists every in-scope
battle driver exactly once and assigns each row to one of:

- `QNT-CONNECTOR`
- `QNT-BLOCKER`
- `RUST-SUBSTRATE`
- `RUST-ROUTE-MIGRATION`
- `HARNESS-GAP`
- `CATALOG-DEFER`
- `REPLAY-REFRESH`

The seed plan must not mark itself complete merely because research was done.
It closes only when the expanded implementation plan exists and is ready for a
separate Ralph run.

## Expansion Rules

Research/classification tasks may append child tasks only from the allowed
task kinds above. They must not create arbitrary prose-only follow-ups.

Every generated child task must state:

- exact driver path or fixed driver group;
- exact route class;
- exact QNT connector or blocker path;
- exact durable reducer owner;
- input files;
- output files;
- acceptance command;
- forbidden shortcuts.

Expansion caps:

- Each classification task may append at most 12 child tasks.
- Each source QNT connector pilot may append at most 8 connector tasks.
- Each Rust substrate task may append at most 6 migration tasks.
- The final expanded plan must estimate min/likely/max remaining task count and
  explain every count.

Forbidden shortcuts:

- no production dispatch on authored identity or fixture identity;
- no driver-local duplicate state where `BattleState` can own it;
- no metadata-only target replay evidence;
- no selected-identity route before the generic substrate exists;
- no broad adapter quarantine as a clean acceptance strategy;
- no dirty cleanroom history used as fresh evidence.

## Parallelization Model

This seed plan is parallelizable after `RRCONV-01` lands and creates the shared
backlog artifact. Do not parallelize before the denominator/backlog schema
exists; otherwise lanes will invent incompatible row shapes and duplicate
driver classification.

Recommended maximum: 5 lanes.

Lane ownership:

1. Source classification lane:
   - Owns `RRCONV-06` through `RRCONV-12`.
   - Writes only route-class/backlog rows and generated child task rows.
   - Does not edit harness code or dirty Rust code.
2. Harness/evidence lane:
   - Owns `RRCONV-03`, `RRCONV-04`, `RRCONV-05`, and `RRCONV-27`.
   - Writes only source scaffold/checker/guidance artifacts.
   - Does not classify drivers except to create negative/positive fixtures for
     evidence rules.
3. Dirty Rust architecture lane:
   - Owns `RRCONV-02`, `RRCONV-17`, `RRCONV-18`, `RRCONV-19`, and `RRCONV-22`.
   - Writes only dirty cleanroom audit notes or source-side task descriptions
     until a later implementation run explicitly targets the dirty cleanroom.
4. Dirty Rust owner-substrate lane:
   - Owns `RRCONV-23` through `RRCONV-26`.
   - Depends on lane 3's entrypoint/participant decisions.
   - May append owner-specific child tasks, but must not classify unrelated
     drivers.
5. Integration/backlog lane:
   - Owns `RRCONV-13`, `RRCONV-14`, `RRCONV-28` through `RRCONV-33`.
   - Merges the outputs of other lanes into one non-overlapping expanded plan.

No-rework rules:

- A driver may be classified by exactly one classification task. If a driver
  appears relevant to two groups, the first task that owns it must add a
  `relatedDriverPaths` note rather than creating a second row.
- Only the integration lane may change route class after initial
  classification, and only with a recorded reviewer-loop finding.
- Harness tasks must not append driver migration tasks; they append only
  `HARNESS-GAP` tasks.
- Rust substrate tasks must not create QNT connector tasks; they may only point
  to existing backlog rows and append `RUST-SUBSTRATE` or
  `RUST-ROUTE-MIGRATION` tasks.
- Selected-identity tasks are owned by `RRCONV-11` and `RRCONV-31`; other lanes
  may record dependencies on them but must not route them by identity.
