This Ralph queue finishes FULL level 7 and adds FULL level 8 to the same
accounting standard as existing golden scopes. FULL means gate-equivalent
completeness: supported runtime and QNT rows have evidence; non-runtime rows
have precise checker-owned closure; future-owner rows are explicit and
non-vacuous. FULL does not mean forcing class table bookkeeping directly into
battle runtime.

```bash

```

## Lane Rules

- Use pnpm only. Never use npm.
- Use local SRD 5.2.1 only. If required rule text is missing from
  `.references/srd-5.2.1/`, stop and report the missing source.
- Keep provenance, structured input, and runtime projection distinct.
- Do not copy PHB+ authored identity. All new non-SRD examples must be visibly
  synthetic.
- Runtime support must not dispatch on authored Unit id, name, slug, provenance
  section, or class/spell identity.
- Do not add duplicate state. Before adding fields, search for existing facts in
  Quint, runtime, Surface, MCP, and React layers.
- Non-runtime class table, ASI, spell-access, and future-owner rows must be
  checker-owned and precise. Do not claim runtime support for a table-only row.
- If a row is closed outside promoted runtime, the closure must name the owner,
  boundary facts, and what future promotion would have to implement.
- If a task narrows scope, it must preserve remaining desired work as concrete
  Ralph tasks, not prose-only notes.
- Do not run MBT for exploratory questions. Run focused MBT only after runtime
  or QNT behavior changes are complete, one MBT process at a time.
