# Battle Authority Inventory

Date: 2026-05-01

Scope: BA1 source-only inventory of the old root/Core battle authority surface. This document classifies old `battle.qnt`, Core `battle-machine*`, Core battle MBT, and Restore Ledger references so BA3 can split downstream reconciliation without re-reading the entire old battle stack.

This inventory does not model new rules. RAW and `ASSUMPTIONS.md` anchors are naming/classification anchors only.

Classification values:

- `overlap-must-match` - promoted runtime already implements the behavior and reconciliation should preserve/align semantics.
- `partial-overlap` - promoted runtime implements a narrower or differently-shaped subset.
- `old-only-width` - old Core models behavior not currently promoted; convert to future width/restoration work before treating it as active runtime behavior.
- `obsolete-core-artifact` - old implementation vocabulary or adapter shape should not be restored as architecture.
- `proof-source-only` - useful as historical proof/reference, not an active behavior owner.
- `needs-owner-decision` - BA3 needs an explicit product/architecture choice.

## Owner Decisions For BA3

No inventory row requires a rules-content decision before BA3, but BA3 should make these architecture/scoping choices explicitly:

1. Should BA4 include only promoted Attack/HP behavior or also old attack-window reactions?
   Options: keep BA4 to promoted hit/damage/HP overlap and send reactions to BA12; or split a new reaction-overlap task before BA12. Recommended: keep BA4 narrow because promoted runtime has no reaction windows.
2. Should BA5 include old Dash/Dodge/Disengage/Ready because they are action-economy actions?
   Options: include only resource/reset/end-turn overlap; or widen BA5 to old action catalog. Recommended: keep BA5 to resource/end-turn overlap and send old action catalog to BA12.
3. Should root `battle.qnt` be retained as an archival proof source after BA8, or should selected old functions be copied into a legacy reference document before quarantine?
   Options: retain root `battle.qnt` with legacy naming; move/copy references into docs; delete after Restore Ledger rows. Recommended: decide in BA8/BA9 after BA2 shows promoted proof gaps.
