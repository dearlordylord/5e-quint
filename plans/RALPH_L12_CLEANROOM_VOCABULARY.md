# Ralph L1-2 Cleanroom Vocabulary

This file separates D&D/SRD language from project verification language for the
L1-2 cleanroom replay plan.

## Rulebook Language

These are D&D/SRD terms:

- spell
- class feature
- action
- attack roll
- saving throw
- damage
- condition
- creature
- target
- duration
- effect

## Project Accounting Language

- `row` means an SRD L1-2 rule entry in the project accounting table. It is
  identified by a `rowId` in the generated JSON artifacts.
- `executable row` means an SRD L1-2 rule entry whose behavior is specific
  enough for the cleanroom harness to run. It does not mean the SRD rule is
  "passing" or "failing"; it only means this project has a runnable verification
  path for that entry.
- `replay` means a cleanroom harness run for the listed SRD rule entries. It is
  not a rulebook term.
- `target` means the generated cleanroom implementation, not the source repo.
- `target replay evidence` is the legacy schema/file naming around the
  machine-checkable cleanroom run result. In human prose, prefer `cleanroom run
  reference` or `compact cleanroom receipt`.

## Cleanroom Run Reference

A cleanroom run reference is the small machine-checkable handle the source
harness reads. It may be a compact receipt stored in source, or a source-stored
manifest entry that points to a retained cleanroom artifact by path/URI plus
content hash.

It is not raw cleanroom logs. Detailed logs and full run history remain in the
cleanroom target or an external artifact store.

It is valid for this plan only when `pnpm cleanroom-harness:check` can read or
resolve it and find all of these facts:

- the reference says it was generated by the target harness;
- the reference names the retained cleanroom artifact path/URI and content hash,
  unless the reference itself is the compact receipt;
- it names the source commit copied into the cleanroom manifest;
- it names the source branch inventory hash used by the run;
- it names the target profile and matching target profile hash;
- every run entry names its driver path, QNT file hash, branch family, branch
  action, observed action, harness test path, and trace id;
- every completed run entry has `result.tag` set to `pass`;
- the observed action equals the branch action;
- the QNT file hash matches the copied source inventory;
- the state projection names what was checked, the comparator used, and the
  target state fields checked;
- the expected projection hash and observed projection hash are equal;
- the observed projection source is a focused generic `qRoute`, focused generic
  `qComponentRoute`, or the equivalent machine proof required by that batch;
- `l12CleanroomGeneration.artifacts[]` lists exactly the copied L1-2 artifact
  paths and hashes from the cleanroom manifest.

If any of those facts is absent or wrong, the SRD rule entry is not a
"non-passed rule." The Ralph task is simply unfinished or wrong and must be
fixed before that entry can be marked done in this plan.

## Done

For this plan, a listed SRD L1-2 rule entry is done only when a cleanroom harness
run reference or compact receipt covers it and `pnpm cleanroom-harness:check`
passes.

Grouped selected-identity proof, source-side accounting, source strict gates,
diagnostic tests, and prose reports do not make a listed rule entry done in this
plan. Raw cleanroom logs checked into source are not required and are not the
close condition.
