request to produce another planning document. Running it means changing the
owning product artifacts, proofs, runtime tests, generated evidence, and gates
until level-1-10 support converges.

If the user says "implement this plan", the next action is implementation, not
plan maintenance. A Ralph agent must read the current strict blocker report,
pick the smallest runnable level-10 blocker, change its real owner, run focused
verification, regenerate strict artifacts, and continue.

task split is a failed implementation run unless the latest user request
explicitly asks for planning-only maintenance.

## Scope

FULL level 1-10 support means playable, product-complete support for every SRD
Unit reachable by character level 10. This includes the complete level-10 class
and subclass feature frontier, all level-10 class table and character sheet
progression facts, all spell-access changes reachable at level 10, and the
spell-level-5 support frontier carried forward from level 9.

Character level 10 does not introduce spell-level-6 access. Full casters first
reach spell-level-6 at character level 11, and Warlock Mystic Arcanum also
starts at Warlock level 11. Level-1-10 support must therefore retain
spell-level-5 closure and add explicit tests proving no spell-level-6 ordinary
access leaks into level 10.

The following states may appear only as intermediate blockers and do not close
in-scope level-10 support:

- `unsupported-profile`
- `catalog-only/dead-for-now`
- `future-owner`
- `missing-authored-record`
- `missing-authored-runtime-closed`
- `closed-later-level-only` for `firstTriggerCharacterLevel: 10`
- `class-progression-follow-up-required`
- MCP `reuse-existing-evidence` or audit-only closure

Non-battle rules still need implemented support at the correct owner: Surface,
Character Creation, Character Sheet/session, Spell Access, MCP/session tooling,
rules-kernel evidence, or table-facing API. "Not battle
runtime" is a routing decision, not a completion state.

  finding, explicitly reject only with a concrete reason, and repeat until no
  reasonable findings remain.

  change, run `pnpm unit-profile-coverage:check --write`, then rerun
  `pnpm unit-profile-coverage:check`.

  implementation, with one MBT run at a time and the mandatory
  timing/progress wrapper.
