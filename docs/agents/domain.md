# Domain Documentation

This is a multi-context repository. Before exploring or changing a domain,
read [`CONTEXT-MAP.md`](../../CONTEXT-MAP.md) and follow it to the authorities
relevant to the work. Do not create a root `CONTEXT.md` or a parallel glossary.

The context map distinguishes D&D/SRD language, Cleanroom SDK language,
Mushroom Playbook language, architecture, modeling assumptions, package-local
boundaries, and accepted specifications. Keep each fact in the single owner
named there and link to that owner elsewhere.

Read accepted ADRs that affect the area being changed. Use the vocabulary from
the relevant context document in issue titles, design discussion, code, and
tests. If a proposed decision contradicts an accepted ADR or an owning context,
surface the conflict instead of silently replacing its language.

For Wayfinder promotion and deletion, follow the rule in
[`CONTEXT-MAP.md`](../../CONTEXT-MAP.md).
