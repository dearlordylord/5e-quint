# Light, obscurement, cover, and sight are runtime source-facts plus table-supplied witnesses

RAW gives precise mechanical consequences for illumination, obscurement, cover, and sight, but it does not make the battle reducer responsible for whether a torch shines around a corner, whether a wall grants Total Cover, or whether one creature can see another right now. So battle runtime splits the concern: it **stores durable source-owned facts** that spells, features, or items create, and it **consumes table-supplied projection witnesses** at the point a rule needs table knowledge. The runtime applies RAW consequences from those source facts and witnesses; it never computes geometry, line of sight, or illuminated squares. This is the visibility case of the broader spatial boundary in ARCHITECTURE.md "Spatial Modeling Frontier".

Source facts are kept as separate but parallel domain nouns: `LightEmitter` describes what a source emits (Bright/Dim Light, attachment, shape/radius, expiration) and `ObscurementZone` describes what a source creates (Lightly/Heavily Obscured area, source, area id, shape/radius, expiration). Light, obscurement, cover, and sight stay distinct named concepts rather than one "visibility" bucket. Sight is a per-action **witness**, never durable pairwise state, and it is **directional**: "the attacker can see the target" and "the target can see the attacker" are separate questions, neither inferred from the other. Attack-roll mode is computed from the final combined set of advantage/disadvantage sources — an unseen target contributes Disadvantage, an unseen attacker contributes Advantage, and mutual unseen cancels to a normal roll (RAW cancellation). Downstream rules such as Rogue Sneak Attack consume that final mode, not one sight source in isolation. Holes carry reducer-derived requirements (e.g., the maximum distance a rule cares about); fills carry only the table fact (the witnessed distance or yes/no) and cannot restate or override authored RAW constants.

## Considered options

- **A map/geometry engine in runtime** (grid, pathfinding, line-of-sight, cover geometry, persistent map) — rejected; the table owns geometry, the runtime owns the mechanical consequence. There is no test that expects the runtime to infer whether a creature is inside a fog cloud.
- **A single collapsed "visibility" state field** — rejected; later magical Darkness, Darkvision, Blindsight, and Truesight work would require undoing a collapsed model. The separate nouns leave clean extension points.
- **Durable pairwise `canSee` state** — rejected; it duplicates table projection facts and would be recomputed every turn. Hidden and Invisible are runtime-owned because they are mechanical facts with runtime lifetimes; sight is supplied per action, reaction, search, Hide, or targeting resolution.
- **A broad sight algebra up front** — rejected; if a pure helper becomes useful it stays a small consequence helper over already-established facts (e.g., attack-roll mode from caller-supplied sight and condition facts), not a geometry owner.

## Consequences

- Landed in `packages/battle-runtime`: `battle-runtime-light.qnt`, fog-cloud tests, and `ObscurementZone`/`LightEmitter` source facts in the reducer (`spells-active-effects.ts`, `battle-codecs.ts`). Produce Flame, Faerie Fire, and Fog Cloud are modeled through this boundary.
- Hide eligibility is a table-supplied basis named in RAW terms (Heavily Obscured, sufficient Cover, out of line of sight, or a modeled trait override), not a runtime geometry computation.
- Deliberately deferred, with room left rather than falsely claimed solved: magical Darkness, nonmagical light suppression, Daylight overlap/dispel reciprocity, and Darkvision/Blindsight/Truesight/Tremorsense/Devil's Sight special-sense projection.
